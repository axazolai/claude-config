# План: локальная модель (DeepSeek V4.1 Flash) для экономии токенов Claude Code

## Исходные данные разведки

| Параметр | Значение |
|---|---|
| Модель / сервер | DeepSeek V4.1 Flash, SGLang, 4 GPU |
| Заявленный контекст | 1 048 576 токенов |
| Проверенный контекст | иголка на 18k (2,4 с) и 94k (12,2 с), префилл ~7,5k ток/с |
| Конкурентность | `max_running_requests=32` на всех пользователей сервера |
| Парсеры | tools и reasoning включены (`deepseekv41`, `deepseek-v41`) |

Принцип: Claude Code остаётся «мозгом» (планирование, архитектура, отладка, финальное ревью), локальная модель берёт объёмное и механическое (чтение, суммаризация, шаблонный код, коммиты).

```
Фаза 1. Проверка  ->  [гейт: tool calls и кэш работают]
Фаза 2. Инструменты  ->  [гейт: smoke-тест пройден]
Фаза 3. Правила для Claude Code
```

## Фаза 1. Проверка и тестирование возможностей

Результат: таблица «что можно отдавать модели» с цифрами.

### 1.1 Tool calling
- 10–20 реальных траекторий Claude Code (чтение файлов, grep, правки, bash).
- Критерий: ≥90% валидных вызовов без ручных правок.
- Если не проходит, роутер (фаза 2) не делаем, остаёмся на MCP-инструментах.

### 1.2 Thinking и prefix-кэш
- Переключение thinking флагом (`chat_template_kwargs: {"thinking": false}`, точное имя зависит от шаблона).
- Замер латентности и качества с thinking и без него на суммаризации и генерации тестов.
- Кэш: два запроса с одинаковым префиксом, второй должен быть заметно быстрее. Проверить, что RadixAttention не отключён флагом.

### 1.3 Длинный контекст
- Иголка на 200k и 500k.
- Multi-needle (3–5 фактов, разбросанных по тексту).
- Реальная задача: суммаризация большого модуля с проверкой деталей.
- Итог: зафиксировать рабочий потолок (ожидание ~100–150k) и использовать его как лимит в инструментах.

### 1.4 Нагрузка и латентность
- 1, 3 и 8 параллельных запросов, p50/p95.
- Замер влияния на других пользователей сервера (общий лимит 32).
- Итог: числа для лимитов параллельности и таймаутов фазы 3.

**Гейт 1:** tool calls стабильны, кэш работает, рабочий контекст и безопасный уровень параллельности определены.

## Фаза 2. Создание инструментов взаимодействия

Результат: работающий стенд, который можно вызвать вручную и из Claude Code.

### 2.1 MCP-сервер «локальный исполнитель»
Инструменты:
- `local_ask(question, paths[])`: загрузка файлов в модель, возврат только ответа. Дамп кода в начале промпта, вопрос в конце (под prefix cache).
- `local_summarize(path|text, max_words)`: выжимка файлов, логов, диффов, вывода тестов.
- `local_commit_msg(diff)`: коммит-сообщения, PR-описания.
- Опционально: `local_draft(spec)` для шаблонного кода и тестов.

Внутри каждого инструмента:
- семафор на 2–3 параллельных запроса, очередь с отказом после 30 с;
- таймауты (см. фазу 3);
- флаг thinking по типу задачи (выкл для summarize/commit, вкл для draft);
- retry с backoff (один повтор);
- единый формат ошибок: `{ok:false, reason: "timeout|unavailable|bad_output", ...}`;
- лимит входа в токенах (рабочий потолок из 1.3).

### 2.2 Скрипты и CLI
- `health`: ping, `/v1/models`, тестовая генерация на 5 токенов.
- `bench`: повтор тестов фазы 1 для регрессий.
- `warm`: прогрев prefix-кэша для крупных репозиториев.
- Общий конфиг: URL, имя модели, лимиты, таймауты.

### 2.3 Хуки и роутер
- Хук на вывод `Bash`: если вывод больше порога (билд, pytest, docker logs), сжимать локальной моделью и оставлять хвост с ошибками.
- Роутер (LiteLLM или claude-code-router): Explore, фоновые задачи и сабагенты на локальную модель, основной цикл на Claude. Делаем только если гейт 1 по tool calls пройден уверенно.
- Проверить: принимает ли SGLang формат Anthropic напрямую или нужна конвертация.

**Гейт 2:** smoke-тест (health, ask, summarize, commit, хук) проходит; отказ бэкенда обрабатывается без зависаний.

## Фаза 3. Правила для самого Claude Code

Результат: предсказуемое поведение при любых сбоях и нагрузке.

### 3.1 CLAUDE.md и скилы
- Когда звать локальную модель: чтение файлов >300 строк, логи, вопросы «где/как реализовано X», коммиты, шаблонный код и тесты.
- Когда не звать: рефакторинг на несколько файлов, архитектурные решения, отладка неочевидных багов, финальное ревью.
- Скилы: `local-ask`, `local-summarize` с краткой инструкцией и примерами.

### 3.2 Сабагент-исполнитель (`.claude/agents/`)
- Вызывает только `local_*` инструменты.
- Возвращает выжимку не длиннее N слов.
- При ошибке инструмента сразу сообщает об этом и не пытается чинить сам.

### 3.3 Правила деградации

| Ситуация | Поведение |
|---|---|
| Бэкенд недоступен | `health` не прошёл или 2 таймаута подряд: флаг «модель выключена» на 10 минут, Claude работает сам, без повторных попыток |
| Падение качества | Пустой или обрезанный ответ, невалидный JSON, в ответе нет запрошенных путей: один повтор, затем Claude берёт задачу на себя |
| Проверка выжимки | Для критичных мест Claude сверяет 1–2 факта по исходнику |
| Параллельность | Не более 2–3 запросов одновременно, остальные в очередь, отказ после 30 с |
| Время реакции | Таймаут 60 с для `ask`, 20 с для `summarize` и `commit`; при превышении fallback на Claude |
| Возврат в работу | После окна отключения один пробный запрос `health`, затем штатный режим |

### 3.4 Контроль эффекта
- Через неделю сравнить `/cost` до и после.
- Логировать в MCP: вызовы, токены на входе/выходе, латентность, доля fallback.
- Если fallback >20% или экономия незаметна, пересмотреть пороги или отключить инструмент.
