# Rebase ultrapowers onto upstream 6.4.1 — Implementation Plan

**Goal:** Rebuild the fork on upstream `v6.4.1` with the decisions of `19-SPEC.md` § 1 and the
delta audit of § 2, shipped as `6.4.1-up.1`; fix the installer's `up-update` so it resets the
revision on a new base.

**Architecture:** The fork's `original` gets a parentless commit of `v6.4.1`; `patch` repoints
`transform/config.json` and `inventory.json` at it, classifies the new paths, and carries 13
deltas (001–011, 014, 015) re-authored in filename order over a scratch chain of trees; `main` is
generated by `build-cli commit`. Nothing is pushed or installed without the partner's word.

**Spec:** `19-SPEC.md`.

## Global Constraints

- No `up-update update`/`--publish` run: it works in a throwaway clone and refuses on the 35%
  threshold. The rebase is authored in `../ultrapowers` on branch `patch`.
- `main` and `original` are never hand-edited: `original` comes from `git commit-tree`, `main`
  from `build-cli commit`.
- The fork's working tree holds unrelated `graphify-out/` deletions: stage named paths only.
- Delta text is instructions, not justifications (`CONVENTIONS`). Upstream's `rm -rf` is never
  carried into skill prose.
- Tests follow phase 18: written after the code, one per `Acceptance:` line, run before review.
  Fork deltas are prose: their acceptance is the build and the greps of Task 8.
- Scratch trees live in `claude-config/.claude/.scratchpad/tmp/p19/` and are deleted by name at
  the end.
- No push, no plugin update, no deploy inside this plan (Task 10 asks).

**Branch:** `feat/upstream-6.4.1` here; `patch` in the fork.

### Task 3: Delta chain — keep and small rewrites (001, 003, 004, 005, 006, 010, 011)

**Files (fork):** those seven `transform/deltas/*.patch`.

How (applies to Tasks 3–7): a scratch git repo holds the chain; each delta is applied or
re-authored in filename order, so delta N is always a diff over base + 001..N-1.

```bash
S=../claude-config/.claude/.scratchpad/tmp/p19
node transform/build-cli.mjs emit --base "$S/chain"
git -C "$S/chain" init -q && git -C "$S/chain" add -A && git -C "$S/chain" commit -qm base
# per delta N, in order:
git -C "$S/chain" apply --unidiff-zero "$PWD/transform/deltas/N-*.patch"   # keep
#   or edit files in $S/chain, then:
git -C "$S/chain" diff > transform/deltas/N-name.patch                      # re-author
git -C "$S/chain" add -A && git -C "$S/chain" commit -qm N
```

The written patch keeps `a/plugins/...` / `b/plugins/...` paths (`git diff` in the chain repo
emits them, since the emitted tree is rooted at the repo top).

**Acceptance:**
- 003, 005, 006 apply unchanged.
- 001: the "install fallow" Minor note only when the repo root has `package.json`; otherwise
  the pre-pass is skipped silently.
